RfidManager

RfidManager controls both the external RF88 and the built-in MF52 reader. This reference covers 121 RfidManager methods and 8 utility methods from RfidUtils and MaskSafety, with reader support listed for each method.

Getting started

Add the SDK

You can add the SDK in two ways. We recommend the Maven repository, because Gradle then also downloads the Kotlin standard library the SDK needs. To add it by hand instead, use the files from the Point Mobile portal.

From the Maven repository
The repository is private, so you need an access token from the Point Mobile portal. Set it up in three steps.

Step 1: Add your access token
Open local.properties in your project's root directory (the file that already has sdk.dir) and add your token as shown below. Android Studio's default .gitignore already excludes this file, so the token stays out of version control. On a build server, set the ORG_GRADLE_PROJECT_pointmobileMavenToken environment variable instead.

local.propertiesProperties
# Add your token below the existing sdk.dir line.
pointmobileMavenToken=<your token>

Step 2: Add the repository to settings.gradle.kts or settings.gradle
Put the token lookup above the dependencyResolutionManagement block, and the maven { … } block inside its repositories. With Kotlin DSL, also add the import at the top of the file. The code reads the token from local.properties first and falls back to the Gradle property of the same name. If it finds neither, Gradle sync stops with an error saying the token is missing.

settings.gradle(.kts) 
// Add this import at the top of the file.
import java.util.Properties

// Your existing pluginManagement { … } and plugins { … } blocks stay above this.

// Reads the token from local.properties, or from the Gradle property of the same name.
// On a build server, set the ORG_GRADLE_PROJECT_pointmobileMavenToken environment variable.
val localProperties = Properties().apply {
    val file = settingsDir.resolve("local.properties")
    if (file.isFile) file.inputStream().use { load(it) }
}
val pointmobileMavenToken: String =
    (localProperties.getProperty("pointmobileMavenToken")
        ?: providers.gradleProperty("pointmobileMavenToken").orNull)
        ?.trim()?.takeIf { it.isNotEmpty() }
        ?: throw GradleException("Add pointmobileMavenToken=<your token> to local.properties.")

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        // Add the Point Mobile Maven repository, using the token read above.
        maven {
            url = uri("https://raw.githubusercontent.com/PointMobileSDD/maven/master")
            credentials(HttpHeaderCredentials::class.java) {
                name = "Authorization"
                value = "token $pointmobileMavenToken"
            }
            authentication { create<HttpHeaderAuthentication>("header") }
        }
    }
}

To connect an RF88 over Bluetooth, the app needs both BLUETOOTH_CONNECT and BLUETOOTH_SCAN. The SDK stops Bluetooth discovery before it opens the connection, so with BLUETOOTH_CONNECT alone the connection fails. Those two exist from Android 12 (API 31). On Android 11 and earlier the same calls need BLUETOOTH and BLUETOOTH_ADMIN, so an app that also runs there declares them too, with android:maxSdkVersion="30". The SDK declares none of these permissions itself. The MF52 reader and an RF88 in the cradle need none of them.

Threading: Call synchronous methods that talk to the hardware on a background thread. Async results and listener events arrive on an SDK thread, so switch to the main thread before updating the UI.

Errors: Synchronous connection methods (including disconnect()), inventory methods and tag access methods return a result code from ResultCode. For other return values and how each method reports failure, see its description. Asynchronous methods pass an RfidException to onFailure; decide what to do from its error code. An asynchronous tag access method calls onSuccess only when the operation succeeded; any other result code — a tag's 04 or 0B as well as the SDK's own E1 or E2 — goes to onFailure, in RfidException.resultCode. Tag operation failures — including an inventory whose start was refused and each tag whose read failed during inventory-and-read — are also reported to OnOperationStateChangedListener.onOperationFailed with the same result code.

Cleanup: stop() only asks the reader to stop. Poll isOperationRunning() until it returns false before you send the next command. When your app is done with the reader, call disconnect() on a background thread and unregister your listeners by passing null to their setters.

Call getSdkVersion() to identify the SDK version. Log it when your app starts and include it when you contact support.

Result codes

Tag operation results start with a two-character result code. E0–E4 mean the SDK rejected the command before it reached a tag (E2 can also mean the reader refused an argument); the other codes come from the reader or the tag. The SDK also uses FF as a compatibility fallback, so FF alone doesn't tell you whether the command was sent. Compare codes against the ResultCode constants, and use ResultCode.isSdkLocal() to spot E0–E4.

SDK error codes
Command rejected
Check the connection, the running operation, the arguments, reader support, and the license.
E0No reader was connected.
E1The command was not executed because the reader was busy. Possible causes include an active operation, a command running on another thread, a connection attempt in progress, or an active connection to the other reader. Retry when the reader is ready. isOperationRunning() tracks only inventory and tag access operations, so it can return false even when this code is returned.
E2An argument was rejected by the SDK before the command was sent, or by the reader. No changes were applied.
E3The reader does not support the requested operation or setting.
E4The reader does not have a valid license.
Reader and tag result codes
Operation result
FF can mean a timeout or a compatibility fallback. On its own, it doesn't tell you whether the command was sent.
01The operation succeeded.
00The reader reported a failure without specifying a cause.
03The requested address exceeds the memory bank capacity.
04The memory is locked for this operation.
0BThe tag received insufficient power to complete the operation. This indicates insufficient tag power rather than an invalid argument.
0FA tag error with no specific cause.
11A tag error with no specific cause (a separate result code).
8EThe Select mask format is invalid.
90A reader error with no specific cause.
92The write length does not match the data length.
94The access password was rejected.
D0The tag did not respond.
D1The tag rejected the operation because access was not authorized.
D2A Kill operation was attempted with a zero password.
D3The tag does not support the requested operation.
D4An internal reader error.
FFTimeout or compatibility fallback. Whether the command was sent is unknown.

Verify the result even when you get a success code. Read the data back after a write, and check lock results separately. A lock can return 01 without taking effect if the access password is zero. PERMA_LOCK and PERMA_OPEN can't be undone.

A read returns the code and the data in one string, such as "01 A5A5". Split them with ResultCode.codeOf() and ResultCode.dataOf(), or check for success with ResultCode.isSuccessful(). Don't compare the whole string with "01".

An inventory method's result code indicates whether the request was sent to the reader. OperationState.STARTED confirms that the reader started the operation. To check whether the operation has ended, call isOperationRunning(); it returns false when no inventory or tag access operation is running.

Reader-specific values

The same setting can take different values on each reader. getRegion() and getLinkProfile() use each reader's own numbering, and the SDK passes those numbers through unchanged.

Don't reuse a setting value read from one reader on the other. Ask the connected reader with getSupportedRegions(), getSupportedLinkProfiles(), and getSupportedPowers(), and pick a value from what it returns. The same number can mean different things on each reader: region 3 is Hong Kong on the RF88 but ETSI on the MF52. Checking support doesn't make the values interchangeable.

For common Gen2 settings such as memory bank, session, and Select action, use the ConfigValue constants. Both readers set transmit power in units of 0.1 dBm, and the RF88's maximum, 300, is 30 dBm (1 W).

Tag read and write addresses count in 16-bit words, and EPC data starts at word 2. Select mask offsets count in bits. Before a masked write, lock, or Kill, call MaskSafety.explainUnsafe() to check the tag selection settings; if they're unsafe, it tells you why.
