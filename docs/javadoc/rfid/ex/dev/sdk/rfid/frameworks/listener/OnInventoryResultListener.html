Interface OnInventoryResultListener

  • All Implemented Interfaces:
    
public interface OnInventoryResultListener

    Tags seen during inventory.

    Readers: RF88 · MF52. onInventoryDiscovered comes from both; onInventoryAndReadDiscovered only ever from the RF88, because only the RF88 reads during inventory.

    A reader that cannot supply a value supplies an empty string, never null. The MF52 has no carrier frequency to report; the RF88 carries RSSI, frequency and checksum only when RfidManager.setPacketOption asks for them. Branch on isEmpty(), and do not read an empty field as a measured zero.

    Fires on an SDK thread — not the caller's, not the main thread. Marshal to your own thread if your UI needs it. Calling back into the SDK from here is allowed.

    Return quickly. Reports and the other host callbacks are delivered one at a time on the SDK callback thread, so time spent here delays everything queued behind it. It does not block the reader's protocol callback thread. Hand expensive work to your own thread and come back.

         Unit onInventoryDiscovered(String data, String ascii, String rssi, String frequency, String checksum)

        A tag was observed.

        Parameters:
        data - EPC as uppercase hex.
        ascii - data decoded as printable ASCII, non-printable bytes shown as ..
        rssi - Signal strength in dBm, signed — the RF88 reports one decimal place (-32.4), the MF52 a whole number (-65).
        frequency - Carrier frequency the tag was read on, in MHz to three decimal places ("926.750").
        checksum - The check value that came with this read.

      • onInventoryDiscovered

         Unit onInventoryDiscovered(String epc, String ascii, String rssi, String frequency, String crc, String pc)

        Reports a detected tag, including the PC word in addition to the five-argument callback values.

        Override this one or the one above, not both. The SDK calls this one and nothing else. Its default implementation passes the same values on to the five-argument form, so a host written against that one keeps working and never sees this method.

        The first five parameters match the values delivered by the five-argument overload. The names epc and crc clarify the meanings of the older data and checksum parameters.

        Parameters:
        epc - The EPC as uppercase hex, and only the EPC.
        ascii - epc decoded as printable ASCII, non-printable bytes shown as ..
        rssi - Signal strength in dBm — as in the five-argument form.
        frequency - Carrier frequency the tag was read on — as in the five-argument form.
        crc - The tag's CRC that came with this read — the value the five-argument form calls checksum.
        pc - The tag's PC word as four hex digits: the Gen2 protocol control word, which states among other things how long the EPC is.

      • onInventoryAndReadDiscovered

        ascii - data decoded as printable ASCII, non-printable bytes shown as ..
        readData - Payload of the read, as hex.
