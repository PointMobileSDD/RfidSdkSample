Interface OnOperationStateChangedListener

  • All Implemented Interfaces:
    
public interface OnOperationStateChangedListener

    Lifecycle changes for operations accepted by the SDK.

    Readers: RF88 · MF52. Inventory, inventory-and-read, read, write, lock and kill report one OperationState.STARTED followed by one OperationState.FINISHED. The two always come as a pair: an operation that never reports STARTED never reports FINISHED either.

    Three things report neither state. A request refused before it reaches the reader — while disconnected or busy, or because the SDK's own checks turned it down (invalid arguments) — answers through the method's result or async failure callback, and is also reported to onOperationFailed. A request the reader never took reports nothing here. And an operation type this version does not name is not reported at all.

    OperationState.STARTED means the reader accepted the operation, not merely that the SDK asked. For every operation that is the reader taking the command — the sled's acknowledgement, the built-in reader's service accepting the request — which for inventory is also the first moment a tag can arrive. It does not promise that a tag has been seen. If the reader ends the run right away, STARTED can be followed quickly by FINISHED.

    OperationState.FINISHED is a lifecycle signal, not a success result. Read, write, lock and kill report their outcome through their return value or ResultCallback; this callback says only that the operation no longer occupies the reader. The slot is released before FINISHED is delivered, so starting the next command from inside that callback is safe. What did not succeed is reported to onOperationFailed, before FINISHED when the operation had reported STARTED.

    Callbacks arrive one at a time on the SDK callback thread, never the main thread. An exception thrown by a host callback is logged and does not escape into the reader or terminate callback delivery.

      • onOperationFailed

         Unit onOperationFailed(OperationType operation, String resultCode, String epc)

        operation did not succeed.

        Reported for a read, write, lock or kill whose result is not a success and for an inventory or inventory-and-read whose start was refused — resultCode is then the same code the call returns — and for each tag whose read failed during inventory-and-read. For an operation that reported OperationState.STARTED this comes before OperationState.FINISHED; a request refused before it reached the reader reports only this.

        Parameters:
        operation - the operation that did not succeed.
        resultCode - the two-character result code, as defined in ResultCode — for example ResultCode.INVALID_PASSWORD_ERROR (94) when the access password set with RfidManager.setAccessPassword does not match the tag.
        epc - the EPC of the tag the failure concerns, as uppercase hex without the PC word, when the reader named one: each tag whose read failed during inventory-and-read.
