public final class RfidManager

    The entry point for controlling readers supported by this SDK.

    One instance controls the active RF88 or MF52 reader. Calls are routed to the active reader according to the connection state.

    The SDK supports two readers. Each method below lists the readers it supports:
    • RF88 — an external reader the device attaches to. It attaches over Bluetooth (connect) or over the wired connection (connect), and includes its own hardware: a battery, two triggers, a buzzer and a vibrator. An RF88 the device has not paired with can be paired first with pair, so the user is not asked for a PIN.
    • MF52 — a reader built into the device, reached with connectInternal. It does not include the RF88 peripheral hardware and requires a license to operate.

    Each method includes a Readers: section that identifies the supported readers. Where a setting exists on both but takes different values, the @param tag lists the domain per reader. A setting the connected reader does not have is not an error — isSupported returns false, a read gives "" and a write gives UNSUPPORTED.

    An empty string does not establish that a setting is unsupported. A failed read can also return an empty string. After connecting, use isSupported to check support. Each method also lists its supported readers. Use getActiveReader to identify the active reader.

    A key identifies the same setting on both readers, but its value may depend on the reader — getRegion and getLinkProfile are numbered differently on each. Do not store a value read from one reader and write it back to the other. Ask the currently connected reader: getSupportedRegions, getSupportedLinkProfiles, getSupportedPowers. Tag operation results include a two-character result code. Codes E0–E4 are reserved for SDK validation failures and indicate that the command did not reach a tag. The remaining values are reader and tag result codes. FF is the compatibility exception: readers use it for a timeout, and the SDK also uses it as the fallback for failures that have no more specific local code, so FF alone does not prove whether a command was transmitted.

    Unambiguous SDK-local codes — the command did not reach a tag: 

     E0  nothing was connected
 E1  the reader was already running an operation
 E2  an argument was rejected before anything was sent
 E3  the reader does not support the requested operation or setting
 E4  the reader is present but not licensed, or licensed use is turned off

    Reader and tag result codes — normally produced after an exchange: 

     01  succeeded
 00  the reader failed for a reason it did not classify
 03  the requested address exceeds the memory bank capacity
 04  the memory is locked against this operation
 0B  the tag did not have enough power to finish
 0F  tag-side failure, no specific cause
 11  tag-side failure, no specific cause (second code)
 8E  the select mask was malformed
 90  reader-side failure, no specific cause
 92  the write length did not match the payload
 94  the access password was rejected
 FF  timeout or compatibility fallback; transmission is unknown from this code alone
 D0  the tag did not answer at all
 D1  the tag refused for lack of privilege
 D2  a kill was attempted with a zero password, which no tag accepts
 D3  the tag does not implement the operation
 D4  the reader failed internally

    Compare with the constants on ResultCode rather than with literals, and test success with ResultCode.isSuccessful.

    A successful read returns its data with the result code — "01 A5A5": the code, a space, then the payload. Split it with ResultCode.codeOf and ResultCode.dataOf; compare the extracted result code, rather than the full data-bearing string, with "01".

    Connection methods and supported tag access methods have asynchronous counterparts named …Async that accept a ResultCallback. These methods run the same operation on an SDK thread and report the result through the callback. The tag access methods that accept a mask also have asynchronous counterparts; to run lock or kill asynchronously without one, call the mask form with null. Synchronous methods never throw — a failure comes back as a fallback value, or as a ResultCode for calls that return a result code. Asynchronous methods report the failure to ResultCallback.onFailure. An asynchronous tag access method calls onSuccess only when the operation succeeded ("01", and for a read "01" with the data); every other result code goes to onFailure, in RfidException.resultCode.

    Configuration accessors do not have asynchronous counterparts. An accessor marked WorkerThread is synchronous and talks to the reader, which can take anything from a few hundred milliseconds to several seconds. Call those from your own background thread, or provide an asynchronous wrapper similar to readAsync. The ones marked AnyThread only read memory the SDK already holds and can be called from anywhere.

    Calling a synchronous method on the main thread logs a warning. Hardware communication can block the UI, so use a background thread. Methods that reach the reader are marked WorkerThread; the handful that only read memory are marked AnyThread.

    Listener callbacks arrive on an SDK thread, never the main thread; switch to the main thread before updating the UI. The same holds for ResultCallback — it arrives on the same SDK thread as the listeners, so one rule covers every callback this class makes.

    Asynchronous methods run one at a time, in the order they were called, on an SDK thread of their own. A listener callback is not held up while an async call waits for the reader, and an async call starts without waiting for listener callbacks; its result still arrives in order behind them.

    Calling back into this class from a listener is permitted. In particular, the reader slot is free before OnOperationStateChangedListener reports FINISHED, so starting the next command from that callback is safe. A synchronous call made there holds up later callbacks until it returns.

      • init

        @AnyThread() static void init(@NonNull() Context context)

        Initializes audio playback for tag notifications. This method is optional and affects only the tag notification sound.

        Call it once, from Application.onCreate. Only the application Context is kept, so this cannot leak an Activity, and calling it again does nothing.

        The MF52 uses the device speaker to play tag notification sounds. An RF88 beeps in hardware and needs nothing here. The MF52 has no buzzer, so the SDK plays the tone through the device's speaker instead, under the same setting an RF88 uses — setBuzzerVolume with "1" to turn it on, "0" off. Loudness follows the device media volume and the volume keys.

        If this method is not called, all other SDK features remain available. The sound setting is retained, but no sound is played, and the SDK logs the reason once as an error under the tag Rfid-SDK.

        Readers: MF52 only. The RF88 beeps in hardware and needs nothing here; calling this on a device that only ever sees an RF88 is harmless and does nothing.

        Parameters:
        context - any Context.

      • connect

        @WorkerThread()@NonNull() String connect(String address)

        Connects the reader that attaches over Bluetooth, at address.

        The RF88 supports Bluetooth and wired connections. The address is the RF88's Bluetooth address in uppercase, 00:11:22:33:AA:BB.

        Readers: RF88 only. The MF52 does not attach this way — use connectInternal.

        Both Bluetooth permissions are required. The SDK cancels discovery before opening the socket, so BLUETOOTH_SCAN is required alongside BLUETOOTH_CONNECT. A connection attempt fails with an I/O error if the app has only BLUETOOTH_CONNECT permission. Both exist from Android 12 (API 31); on Android 11 and earlier the same calls need BLUETOOTH and BLUETOOTH_ADMIN instead. The SDK declares none of these permissions, so the app declares them.

        This is a synchronous call: it waits for the connection attempt to finish. Call it on a background thread. The return value indicates the outcome. Exceptions are not propagated to the caller.

        Register OnConnectionStateChangedListener before connecting to observe state changes. A link can be lost again afterwards, so keep observing them and handle later operation failures.

        Already connected. If the RF88 is already connected to this address, the call returns SUCCESS at once and changes nothing; listeners are not told again. If it is connected any other way — to another address, or over the wired connection — the call is refused with BUSY; disconnect first.

        One reader at a time. While another reader is connected, or while a connection attempt is still running, this call is refused with BUSY and changes nothing — disconnect that reader first, or wait for the attempt to return.

        A request refused because another reader holds the link does not change the current state or notify listeners. Check the returned result code to detect rejection. The no-argument getConnectionState may still report CONNECTED for another reader; use getConnectionState to query a specific reader.

        A malformed address is refused differently: nothing is attempted, but the RF88's state becomes FAILURE and listeners are told, so a host that watches only the listener still learns of it.

        Parameters:
        address - the RF88's Bluetooth address in uppercase, "00:11:22:33:AA:BB".
        Returns:

        SUCCESS once the connection is established, or at once when the RF88 is already connected to this address; BUSY when another reader or another link holds it, or a connection attempt is still running; INVALID_PARAM for a malformed address; TIMEOUT when the link opened but the RF88 did not answer in time; or NOT_CONNECTED when the attempt finished without a link. Never throws.

        Readers: MF52 only. The RF88 is reached with connect or connect.

      • factoryDefaults

        @WorkerThread()@NonNull() String factoryDefaults()

        Returns every setting of the reader to its default value.

        All configured settings are reset, including transmit power and region. If the default region is not the one for your country, set the region again before reading tags.

        Readers: RF88 · MF52 — each with its own defaults:

           setting                        default
 getPower()                     "250"       25.0 dBm
 getRegion()                    "1"         FCC, the first in getSupportedRegions()
 getLinkProfile()               "0"
 getSession()                   "0"         S0
 getSearchMode()                "1"         single target A
 getSel()                       "ALL"
 getAccessPassword()            "00000000"
 getRssiReporting()             "true"
 getMemoryBank(), getPointer()  "1", "32"   EPC, from bit 32
 getAction(), getTarget()       "0", "4"    the SL flag
 getBuzzerVolume()              "1"         tag sound on
